# GEXFI H5 收益宝 V2 — IT 增量接入说明

## 0. 部署性质
本包是 H5 页面、交互与接口契约交付，不是生产 H5 构建产物。
不得将整个 `prototype/` 或 standalone HTML 覆盖线上 H5。接入现有工程的认证、路由、账务及实际支付服务。
官网 V8 保持不动，现有底部导航“首页 / 汇兑 / 银联卡 / 我的”保持不动。
不要把本包的截图区域当作真实账户UI；它们只用于新增入口定位。

## 2. 付款方式：借鉴交互，不借用商户权限
用户截图可确认：卡充值金额选择、支付宝/微信选项、参考CNY、扫码/收银台、待支付订单、查询/取消。
不能由截图推定：这些渠道支持USDT购买，或卡充值成功的回调可直接作为投资申购成功。
本原型展示：Alipay/WeChat 不可用 + 独立演示收银台。不要把演示开关视为上线授权。
上线前 getPaymentAvailability 必须由后端根据已验证市场、交易目的、产品准入及渠道许可返回真实列表。
无可用渠道时显示不可用状态；不创建收款订单，不提供个人收款码或更换商户用途绕过限制。
订单用途固定为真实的 USDT_PURCHASE，绝不能使用 AI_SUBSCRIPTION / CARD_TOPUP / SOFTWARE_SERVICE 代替。

依据（查询日期2026-10-09）：
Antom《Risk Management Requirements for Overseas Acquirers》：
https://docs.antom.com/ac/Platform/le18gg
该规则 Part A 第46项将虚拟货币买卖列为禁止类；Part B 第1项把预付卡及充值列为限制类。
该区别用于本次支付接入边界，不改动现有真实卡充值业务。

## 3. 一条用户流程，三类独立记录
**付款订单 PAY → 购U订单 BUY → 收益宝申购 SUB/持仓 IN。**
用户不需要重新寻找产品，期限和数量沿途带入；系统必须保留三类记录的关联。

A. 使用合资格余额：申购金额 → 收益条款确认 → 预留 → 受理 → 持仓。
B. 法币购U：申购金额 → 购U报价/支付方式 → 付款 → 核对到账 → 财务放行/兑换执行 → USDT入账 → 收益条款确认 → 预留 → 受理 → 持仓。
法币购U第一版为本次全额购买，不做“部分余额+部分法币”混合扣款。
已有钱包余额不随法币付款被同时扣除。
购U成功后回到原产品确认页，不自动投资；用户放弃申购，USDT仍留在钱包。

## 4. 前台金额与报价
- 用户先指定 USDT 数量，后台反算法币应付总额。
- 必须显示：购U数量、付款币种/总额、有效成交报价、已含价差的说明、额外费用（如有）、报价有效期。
- 商业内部成本与利润无需展示，但不能用“零费用”掩盖已有价差或漏掉客户实际承担的收费。
- 演示价 1 USDT = 7.2100 CNY，额外渠道费0，均非现行报价。不得写死到生产。
- 管理费0.50%已反映于3.80%/4.50%/5.00%目标年化，不在付款时再扣一遍。
- 过期报价重新生成，用户重新确认；不能默默调整应付金额或USDT到账数量。
- 支付订单建立后引用不可变 quoteId，服务器控制报价/付款会话的有效期及锁价义务。

## 5. 状态与资金约束
| 展示状态 | 可申购USDT变化 | 收益持仓变化 |
|---|---|---|
| 待付款/付款返回确认中 | 不增加 | 不建立 |
| 渠道确认已收到付款，待核对 | 不增加 | 不建立 |
| 审核已放行，购U执行中 | 不增加 | 不建立 |
| 实际成交并确认USDT入账 | 增加对应合资格资金批次 | 不自动建立 |
| 客户确认收益申购 | 预留对应资金批次 | 仍等待受理 |
| 申购受理 | 预留转持仓本金 | 开始持有期 |

“已支付”按钮、回跳URL、截图或扫描二维码都不是收款凭据。
服务端确认需校验渠道签名、订单号、币种、金额、付款状态；再执行现有到账审核/财务放行策略。
财务控制不会成为H5客户按钮；仅演示控制可模拟，线上用户不得调用。
展示的每日预计收益从受理确认开始，不从付款时间计息。

## 6. 异常处理
1. 未付款取消：先 cancel_requested，待渠道确认才能变 cancelled。
2. 关闭收银台不是取消；返回后恢复同一订单并查询，不重复创建。
3. 取消或超时后收到付款：进入核对/原路退款；不自动买U，不自动投入新期限。
4. 实收金额、币种、主体不一致：review_required，资金暂存核查，不产生可用USDT。
5. 已付款但未成交：仅在确认未执行兑换后可原路退款。执行结果未知应保持待核查，防止又退款又买U。
6. 购U已成交后用户不申购：资金保留为USDT；后续反向兑换是另一个报价服务。
7. 退款请求不等于退款成功；渠道确认才显示已退款。退回原付款方式，不私自转换USDT。
8. 申购受理前取消/拒绝：只释放USDT预留，不倒退购U成交。
9. 幂等：quote/order创建、渠道回调、财务放行、USDT入账、申购提交、退款各有独立幂等键。
10. 新申购必须再次核验认证、市场和可用额度；支付结果不能跳过申购资格。

## 7. 数据与接口
`fiat-payment-adapter.example.ts` 是新增契约，`host-adapter.example.ts` 是原有收益模块契约。
契约描述不是声称现有后端已有这些接口。IT映射到真实服务，不新建第二套客户或钱包账本。
账务用整数最小单位/Decimal；法币用分，USDT用6位小数；禁止JS浮点数直接写账。
资金批次保留 settledPurchaseId / fundingLotId，杜绝外部USDT被误标为可申购资金。
真实渠道密钥、商户号、回调验签和付款URL签名均只在服务端。

## 8. 移动端收银台
同一手机默认“打开收银台”入口，二维码作为跨设备选项。不得让用户必须扫本机屏幕。
支付跳转使用已验证渠道的安全URL/SDK，域名白名单与返回地址由服务端维护。
返回页只查询现有订单；约3秒轮询、离开/隐藏页面暂停、终态停止、错误退避。
本原型3秒读取的是本地状态，没有真实请求。

两份Memo PDF、正文数据与V1（来自官网V8）保持原文件不变。

HTML中的Demo按钮、地区切换、示例金额、二维码及localStorage模拟账本不能进入生产。

## 10. 建议发布顺序
先feature flag关闭接入 → 校验页面与旧导航 → 沙盒真实渠道测试（仅已获准市场/业务） → 核对财务和账本 → 小范围开启。
回滚时关闭新增入口与新申购，不删除已创建订单、钱包凭证或历史持仓；在途付款继续由后端处理。
